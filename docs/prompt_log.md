# 생성 AI 활용 및 프롬프트 진행 기록

이 문서는 `lidar-avoidance-ml` 프로젝트의 개발·고도화·검증 과정에서 설계, 구현, 시각 자료 제작, 교차 리뷰를 멀티모델로 분담한 흐름과 주요 요청 요약을 순서대로 정리한 기록입니다. 교차 리뷰를 통해 평가 시드 중복과 프리셋 맵 참조 공유 버그를 사전에 발견하고 수정한 과정까지 포함합니다.

---

## 1. 활용 방식 개요

코드 전체를 단일 모델에 한 번에 생성시키지 않고 T3 Code의 멀티모델 위임 기능(`delegate_task`)을 이용해 **설계 → 구현 → 통합 검증 → 교차 코드 리뷰 → 수정** 단계로 역할을 분리했습니다.

- **직접 담당**: 문제 정의, 시연 시나리오 설계(비교 GIF, 기준선 교체, 난이도별 고정 맵 A/B), 수업 실습 코드와의 연계 확인, 최종 채택 여부 결정
- **AI 역할 분담**:
  - **코디네이터 · 문서 (`Gemini 4 Neon`)**: 요구사항 정리, 하위 작업 분배·검증, `README.md`·`docs/guide.md`·`docs/prompt_log.md` 작성
  - **설계 (`GPT 6.2 Astra · xhigh` / 초기 `Claude Opus 5.5`)**: 파일 수정 없이 알고리즘·수정 범위·검증 기준 명세 작성
  - **코드 구현 (`Claude Opus 5.5 · xhigh` / 초기 `GPT 6.2 Sol`)**: 명세 기반 코드 구현 및 테스트 실행
  - **시각 자료 (`GPT 6.2 Astra` / `GPT 6.2 Sol`)**: 설명용 GIF 및 생성 스크립트 작성
  - **교차 코드 리뷰 (`GPT 6.2 Astra · xhigh` / 초기 `Gemini 4 Argon`)**: 구현 모델과 다른 제공사 모델로 버그·엣지케이스 점검

### 2단계. 베이스라인 교체: 단순 직진 → 지도 없는 반응형 LiDAR 회피(APF)

기존 베이스라인은 장애물을 무시하고 직진만 해서 비교 기준으로서 설득력이 부족했습니다. 이 기준선을 반응형 회피 방식으로 교체했습니다.

- **요청 요약**
  - 프로젝트 전체 구조를 재점검한 뒤 오케스트레이션으로 베이스라인 교체를 요청했습니다.
  - 단순 직진 대신 지도 없이 목적지 방향과 라이다 값만 사용하는 간단한 회피 기준선 설계를 요청했습니다.
  - 요금제 제약을 확인한 뒤 설계 담당을 `GPT 6.2 Astra(xhigh)`로 지정했습니다.
- **진행 및 결과**
  - **설계(`GPT 6.2 Astra`)**: 무상태 인공 퍼텐셜 필드(APF) 기준선 명세를 작성했습니다. 입력은 학습 모델과 동일한 28차원만 사용하며 단순 장애물은 회피하되 오목한 지형·좁은 통로에서는 국소 최솟값에 막히도록 설계했습니다.
  - **구현(`Claude Opus 5.5`) 및 문서 동기화(`Gemini 4 Neon`)**: `expert.py`의 `baseline_control()`을 교체하고 UI·CSV 라벨을 `라이다 회피 기준선`으로 통일한 뒤(기존 `Baseline (미학습)` CSV 하위 호환 유지) 20맵 평가를 재측정했습니다.
  - **20맵 평가 변화 (2단계 당시 측정 기준)**: 기존 `20% (4도착 · 16충돌)`에서 `85% (17도착 · 0충돌 · 3시간초과)`로 개선되었습니다. 당시 체크포인트 기준 학습 모델은 Linear 35%, KNN 80%, RandomForest·MLP·1D CNN 100%를 기록했습니다. 이후 재학습해 현재 저장소에 포함된 `results/benchmark_20maps.csv`는 기준선 85%, Linear 35%, KNN 60%, RandomForest 90%, MLP 100%, 1D CNN 95%입니다.
  - **교차 리뷰(`GPT 6.2 Astra`)에서 발견해 수정한 사항**:
    - `[Major]` 실시간 랜덤 맵 시드 카운터가 `1000`부터 시작해 평가용 시드(`1000–1019`)와 19개가 겹치던 기존 버그를 발견했습니다. 실시간 수집 시드를 `2000`번대로 분리하고 `1000–1019`를 건너뛰도록 `app.py`를 수정했습니다.
    - `[Minor]` `NaN`/`inf`, `goal_dist <= 0`, `num_beams <= 0` 방어 코드를 추가하고 요약 차트 x축 라벨 겹침을 `visualizer.py`에서 수정했습니다.

### 3단계. 테스트용 고정 맵 A(Easy) · B(Hard) 재설계

시연에서 환경 복잡도에 따른 학습 모델의 필요성을 분명히 보여주기 위해 고정 맵 A·B를 재설계했습니다.

- **요청 요약**
  - 테스트 탭의 맵 A는 웬만한 모델이 모두 통과하는 쉬운 회피 맵으로, 맵 B는 잘 학습된 모델만 통과하는 복잡한 난코스로 재설계하도록 요청했습니다.
- **진행 및 결과**
  - 사전 실측 결과 기존 맵 A에서는 Linear가 충돌하고 맵 B에서는 기준선·KNN까지 완주해 대비가 약했습니다.
  - **설계(`GPT 6.2 Astra`) → 구현·검증(`Claude Opus 5.5`, 3단계 당시 체크포인트 기준)**:
    - **맵 A · 기본 회피**: 직진 주행은 1.9초 만에 충돌하지만 기본 회피가 가능한 6개 주행기와 A\* 교사 전원이 완주합니다(7/7).
    - **맵 B · 복합 난코스 (당시 체크포인트 기준)**: 라이다 회피 기준선은 시간 초과(18초, 충돌 0), Linear·KNN은 충돌하며 RandomForest·MLP·1D CNN·A\* 교사가 완주했습니다. 이후 재학습한 현재 회귀 체크포인트에서는 맵 B에서 RandomForest만 완주하고 분류 체크포인트에서는 3종 모두 완주합니다.
    - **616회 매트릭스 검증 (당시 체크포인트 기준)**: 고정 맵 2종 × 과제 2종(회귀·분류) × 주기 2종(30Hz·60Hz) × 노이즈 11조건(OFF 1회 + ON 10시드) × 주행기 7종 = 총 616회 에피소드가 각 주행기의 예상 결과와 일치함을 확인했습니다.
    - 버튼 폭(132px)에 맞춰 UI 라벨을 `A · 기본 회피`, `B · 복합 난코스`로 조정했습니다.
  - **교차 리뷰(`GPT 6.2 Astra`)에서 발견해 수정한 사항**:
    - `[Major]` 지도 클릭으로 출발점·목적지를 변경한 뒤 다른 맵으로 이동했다 돌아와도 수정 좌표가 프리셋 원본에 남던 참조 공유 버그를 발견했습니다. `simulator.py`의 `set_preset_map()`에 `copy.deepcopy`를 적용했습니다.
    - `README.md`의 맵 선택 → 레이스 시작 순서와 `docs/guide.md`의 18초 제한 범위를 보완했습니다.

### 4단계. UI 점검 및 수업 실습 코드와의 연계성 확인

발표를 준비하며 UI 버튼 구성과 수업 실습 노트북(`TalkFile_Untitled0.ipynb.ipynb`, 217셀)의 내용을 현재 프로젝트와 대조했습니다.

- **요청 요약**
  - 고정 맵 A/B 중심 흐름에서 `새 랜덤 맵` 버튼의 유지 여부를 검토하도록 요청했습니다.
  - 수업 실습 노트북의 코드와 기법만 응용해 주행 모델을 구현할 수 있는지 확인하고 현재 프로젝트 모델과의 공통점·차이점 정리를 요청했습니다.
  - SVM 알고리즘의 사용 여부와 적용 타당성 검토를 요청했습니다.
- **결과**
  - **UI 결정**: 다양한 장애물 배치에서의 일반화 확인을 위해 `새 랜덤 맵` 버튼은 UI에 유지했습니다.
  - **실습 노트북 단독 구현 검증**: 노트북에 등장한 도구(`LinearRegression`, `LogisticRegression`, `StandardScaler`, `KNeighborsClassifier`, `NumPy`)만 로컬 데이터셋(`data/dataset.npz`)에 적용해 실측했습니다.
    - `LinearRegression`: 20맵 **35%** (NumPy 2차·교차항 추가 시 **75%**)
    - `StandardScaler + LogisticRegression`: 20맵 **70%** (맵 A 완주)
    - `StandardScaler + KNeighborsClassifier`: `n_neighbors`를 20에서 5로 조정 시 20맵 **80% → 95%**, 맵 A·B 완주
    - `predict_proba @ 속도테이블` 연속 조향 응용: 20맵 **95% (충돌 0회)**
  - **모델 대조 정리**:
    - 동일 / 동일 계열: `LogisticRegression`(Linear 분류), `KNeighborsClassifier`(KNN 분류), `LinearRegression` → `Ridge`(Linear 회귀, L2 규제 추가), `StandardScaler`, `PCA`
    - 실전 보완 차이: `Pipeline` 래핑, `class_weight="balanced"`, `KNeighborsClassifier(n_neighbors=7, weights="distance", algorithm="kd_tree")`, 좌우 반전 증강
    - 프로젝트 확장 추가: `KNeighborsRegressor`, `RandomForest`, `PyTorch MLP / 1D CNN`, 규칙 기반 `라이다 회피 기준선(APF)`
  - **SVM 검토**: 현재 프로젝트와 노트북 모두 사용하지 않습니다. 좌우 반전 증강 후 약 2만 행(12,000샘플 중 80% 학습셋 × 2 = 19,200행) 규모에서 `SVC(probability=True)`의 교차 검증 기반 확률 보정 비용과 `SVR`의 2출력 래핑 부담, 기존 5종 구조와의 중복 때문에 미적용 상태를 유지했습니다.

## 4. 작업 과정에서 확인한 점

1. **검증 기준 선제시의 효과**: 막연한 개선 요청보다 지도를 아는 A\*와 지도 없는 학습 모델 비교 GIF, 맵 A 전원 통과와 맵 B 난이도 구분처럼 판별 기준을 수치와 장면으로 명시했을 때 설계와 검증 기준이 흔들리지 않았습니다.
2. **교차 모델 리뷰의 버그 탐지**: 구현(`Claude`)과 리뷰(`GPT`)를 분리하자 평가 시드 중복(데이터 누수 위험)과 프리셋 맵 참조 공유 버그를 사전에 수정할 수 있었습니다. 둘 다 실행 화면만 봐서는 놓치기 쉬운 결함입니다.
3. **수업 실습 코드에서 딥러닝까지의 확장성**: 수업에서 배운 분류 모델만으로도 실제 주행이 가능함을 확인했습니다(`StandardScaler + LogisticRegression`은 맵 A 완주, `StandardScaler + KNeighborsClassifier(n_neighbors=5)`는 맵 A·B 모두 완주). 여기에 연속 속도 제어(회귀)와 빠른 추론을 더해 `RandomForest`·`MLP`·`1D CNN`으로 확장했습니다.
